# Changelog

## Unreleased

- Scenario design writes (upsert, HAR/XHR/Postman/JMX import, validate, archive/duplicate) require **editor** (or admin), not admin-only — matches the product write bar so personal/org editors can import captures. Run **dispatch / fan-out / cancel** and metrics POST stay admin-gated.
- **JMeter step config-complete emit.** HTTP `headers` (map or `[{name,value}]`) emit a per-sampler `HeaderManager` under that sampler's hashTree (before extract/assert); plan-level OPA correlation `HeaderManager` is unchanged — both coexist. Advanced HTTP props: `follow_redirects` (default true), `always_encode` (default false), `connect_timeout_ms` / `response_timeout_ms` (when > 0), `think_ms_rand` → `UniformRandomTimer` when greater than `think_ms`, else `ConstantTimer`. `enabled=false` emits JMX `enabled="false"` and is skipped in validate (still stored in `steps_json`). Extract `match_number` / `template` / `default_value`; assert `assert_type` / `assert_field` / `assume_success`; transaction `include_timers` / `generate_parent_sample`; If `evaluate_all` / `use_expression`; ForEach `use_separator`. Classic ThreadGroup ramp uses `schedule.ramp_seconds` when > 0 (else 10). Validate triage / correlation suggestions include nestable `path` (`[0,"children",1]`) when available. Import best-effort reads enabled + per-HTTP headers.
- **HAR/XHR import keeps lab private hosts.** RFC1918, loopback, and `host.docker.internal` are allowed into steps with warnings; cloud metadata (`169.254.169.254`, `metadata.google.internal`, weird hosts) stay hard-blocked. Dial-pin `isBlockedPerfURL` at validate/dispatch is unchanged — set `OPA_PERF_INTERNAL_HOSTS` for lab runs. Empty import 400 includes skip tallies (`static` / `private` / `OPTIONS` / `blocked` / `empty`).
- Modules: drop the `../Open-*-Go` filesystem `replace` directives from `go.mod` and pin the family libraries at proxy-resolvable versions. The `OPA Checkup` `go-test` step failed on every commit — a CI runner checks out one repository, so `replacement directory ../Open-Auth-Go does not exist` aborted the build before a test ran, and a green tree was reported as a red check. `go test ./...` now passes in a bare checkout with a cold module cache. Local development against live sibling checkouts moves to a gitignored `go.work`, generated by `scripts/dev-go-work.sh`; see `docs/go-modules.md`. No replace directives remain.
- **Reusable journey modules.** A `fragment` step is now emitted once at Test Plan level as a disabled `TestFragmentController`, and every `include` / `link` becomes a `ModuleController` pointing at it by node path — shared by all thread groups including each arrivals segment. Previously a reference was emitted only as an XML comment with the referenced steps copied inline, so a "reusable" journey was really N copies that drifted apart. Import round-trips both the container and the reference.
- Fragment inputs: `include.params` (`{name: value}`) emits a scoped `UserParameters` pre-processor (`per_iteration=false`) inside a marked wrapper controller, so one fragment runs with different values per reference and the values apply only to that reference's samplers. Param names count as bound variables for `unbound_variables[]`. Round-trips through import.
- **Fallback is reported, never implied.** A reference that carries its own children, or names a fragment name shared by two definitions, still expands inline; a reference naming no fragment emits nothing and now **fails** validation instead of silently vanishing from the run. `fragment_references[]` on validate and upsert gives `mode` (`module_reference` / `inline_expansion` / `unresolved`), the resolved `node_path` and the `reason`, and the `honesty` text spells out each one. The emitted plan carries the same verdict as a comment.
- **Synchronised burst (rendezvous).** A `rendezvous` step emits a `SyncTimer` (`groupSize`, `timeoutInMs`) so a designed spike is a real simultaneous burst. `schedule_json.rendezvous` (or `rendezvous_group_size`) is the plan-level form: it gates the journey's first own request, and reports the sampler it landed on — falling back to thread-group level, and saying so, when the journey has no request of its own. JMeter timers are scoped, not sequential, and the docs and UI say which requests a burst covers.
- A burst whose group is larger than the VU count never fills: validate fails with a `rendezvous` triage entry rather than letting threads park for the run. The configured group size is emitted as-is, never quietly clamped.
- **Fix: validate no longer samples logic controllers.** `if` / `while` / `loop` / `foreach` (and their `*_controller` / `for_each` spellings) stay in the flattened list as structural markers, but the 1 VU dry-run had no case for them and fell through to its HTTP branch — where a controller has no `url`, so it fell back to `target_url`. A controller carrying a `method` therefore sent a **real extra request to the target on every validate** and came back in `steps[]` as an HTTP sample with a status code and latency that fed `triage[]` and `correlation_suggestions[]`; one without a `method` failed the journey with an `invalid method "<NIL>"` error instead. Controllers now report as structure (`type`, `name`, `ok: true`, plus `condition` / `loops` + `forever` / `input_var` + `return_var`, and a `note` that JMeter evaluates the controller under load) and issue nothing. The steps a controller wraps are still exercised once each, in flat order, below its marker. The flatten walk and the dry run now read one shared list of controller types so they cannot drift apart again.
- **Fix: recording a schedule fire no longer clobbers a concurrent scenario edit.** The scheduler used to rebuild the entire `load_scenarios` row from a snapshot read before the fire, silently reverting any edit committed in between. Scheduling state moved to its own `opl.load_schedule_state` row, so a fire writes only scheduling columns. `schedule_json.last_fired_at` / `next_fire_at` are still read as a fallback for scenarios written before the split, but no longer written.
- **Leased scheduling: extra replicas stand down instead of double-firing.** Each due occurrence is claimed in `opl.load_schedule_leases` (owner identity, expiry, generation) and arbitrated by insert-settle-arbitrate, since ClickHouse has no compare-and-set. Every claim is recorded, winning or losing, so contention is auditable. An owner that dies mid-run has its lease taken over at the next generation once it expires (`OPL_SCHEDULER_LEASE_SEC`). The guarantee is single-fire under bounded insert skew, not a linearizable lock — see [architecture.md](architecture.md#schedule-leasing) for the assumption and `OPL_SCHEDULER_LEASE_SETTLE_MS`.
- **`opl-orchestrator` does real work.** It previously served `/api/health` and nothing else. It now runs the leased schedule tick and a run reaper, shares the lease table with `opl-api` so both may run, and exposes `/api/orchestrator/state` with per-process counters. Container-level reaping only covers containers the reaping process dispatched; other runs are closed on `OPL_RUN_MAX_SEC`.
- **Run reaper:** runs stuck in `running` are closed on their engine container exit codes (`completed` / `failed`) or, past the deadline, as `error` with the reason recorded. Nothing closed them before, so a crashed engine left a run `running` forever. Reaped runs emit the normal terminal-run notification with `source: "reaper"`.
- Server-side next fire + schedule audit: `GET .../scenarios/{id}/schedule` returns the computed next fire time, `due_now`, and the current lease owner and expiry, so the UI stops guessing. `GET .../scenarios/{id}/schedule/history` and `GET /api/perf/schedules` (+ `/history`) expose the fire history from `opl.load_schedule_fires`.
- Scheduling code split out of `lab_extras.go` into `lab_schedule.go` (behaviour-preserving move, pinned by a table of due/next-fire cases).
- **Fix: parameterised data now reaches the plan.** Scenario datasets emit a real `CSVDataSet` (Test Plan level, one shared iterator for classic VUs and arrivals segments) wired to the `data.csv` the engine writes. Plans stored before this — and raw imported JMX — get the element wired in on upsert / dispatch / export. Previously the data file was written and never read, so `${column}` tokens were sent as literal text with no warning.
- Dataset delimiter honoured end to end: the configured value drives both the `data.csv` write and the emitted `delimiter` prop (single character, or `tab` / `semicolon` / `pipe` / `comma`; tab serialized as `\t`). Defaults: `recycle=true`, `stopThread=false`, `shareMode.all`, `quotedData=true`, `ignoreFirstLine=false` — see [jmeter-perf.md](jmeter-perf.md#defaults-and-why).
- Unbound `${…}` detection: validate returns `unbound_variables[]` plus a `severity: unbound_variable` triage entry and **fails** when a token has no backing dataset column, extractor, ForEach variable, raw-JMX `Argument.name`, or plan built-in; upsert and dispatch responses carry the same list as a warning. Validate's 1 VU dry-run is seeded with the first dataset row.
- CSVDataSet round-trip: import reads `recycle` / `stopThread` / `quotedData` / `ignoreFirstLine` / `shareMode` / `fileEncoding` (previously only string props), and export re-emits them unchanged.
- Multi-worker runs shard `data.csv` rows round-robin when there are at least as many rows as workers (`dataset_sharded` on the run response); fewer rows means every worker gets the full file and rows repeat.
- Notification channels: terminal-run events now fan out to **webhook**, **chat** (incoming-webhook message payload via `OPL_RUN_CHAT_WEBHOOK_URL`) and **email** (SMTP via `OPL_RUN_EMAIL_TO` + the shared `OPA_SMTP_*` block). Same `OPL_RUN_NOTIFY_MODE` / `OPL_RUN_NOTIFY_STATUSES` / `OPL_RUN_WEBHOOK_SECRET` controls; `OPL_RUN_NOTIFY_CHANNELS` restricts the set. `/api/health` `run_notify.channels[]` describes each channel (`configured`, redacted `target`, `reason`) without secrets.
- Notification history: every channel attempt is persisted to `opl.run_notifications` and served by `GET /api/perf/notifications` and `GET /api/perf/runs/{id}/notifications` (`sent` / `failed` / `logged` / `skipped` with a plain reason — an unconfigured channel is reported, never silently dropped). `POST /api/perf/notifications/test` (admin) fires a synthetic terminal event to verify wiring.
- Report / trend templates: named, org+project-scoped layouts in `opl.report_templates` (`GET /api/perf/report-templates`, `POST .../upsert`, `GET/DELETE .../{id}`, `POST .../{id}/archive`). Exports accept `?template=<id>` on `runs/{id}/report`, `runs/{id}/bench-pack` and `scenarios/{id}/trends`; the applied layout (or the plain reason it was not applied) is echoed in the payload and the `X-OPL-Template` header.
- Bench report formats: `GET .../runs/{id}/report?format=html|pdf` (JSON/CSV unchanged); `GET .../runs/{id}/bench-pack` ZIP (JSON+CSV+HTML+PDF+MANIFEST).
- Scenario trends: `GET .../scenarios/{id}/trends` (multi-run points, best/worst p95, SLA breach count).
- Terminal-run notifications: optional webhook (`OPL_RUN_WEBHOOK_URL`) on `completed` / `passed` / `failed` / `cancelled` (and aliases); `OPL_RUN_NOTIFY_MODE=log` for dry-run; optional HMAC `OPL_RUN_WEBHOOK_SECRET`; health exposes `run_notify` without secrets.
- ForEach + Fragment/Link in VU tree → JMX (`ForeachController`, disabled fragment containers, include expand); validate skips fragment defs and expands links.
- Postman Collection import: `POST /api/perf/scenarios/import-postman` (v2/v2.1 → HTTP steps; `{{var}}` → `${var}`).
- Validate auto-correlation: `correlation_suggestions[]` (token/CSRF/Bearer heuristics) alongside triage cards.
- Restore archived scenarios: `POST .../unarchive`; list `?archived=1`.
- Visual editor depth: If / While / Loop controllers in steps → JMX (`IfController` / `WhileController` / `LoopController`) with nested hashTrees; JMX import preserves controller nesting on round-trip.
- Custom load curve: `schedule_json.curve` with `curve_mode=vus|arrivals`. VU mode → peak/ramp/duration ThreadGroup; arrivals mode → open-model start segments (one journey per arrival, rate-shaped). Caps via `OPA_PERF_MAX_ARRIVALS` / `OPA_PERF_MAX_ARRIVAL_RATE`.
- Lab ops: scenario soft-archive + duplicate; `GET /api/perf/load-policies`; run runners live status; per-step stats + report (`?format=csv`); `POST /api/perf/runs/import-jtl`; validate triage (`pass` + `triage[]`); light `schedule_json` scheduler; instrumentation honesty for public vs compose demo hosts.
- JMeter visual editor backend: nested `children` on steps → TransactionController / HTTPSamplerProxy nested hashTrees; `flattenScenarioSteps` for validate.
- Auth: adopt Open-Auth-Go per-user project ACLs (`project_ids` / `EnforceProjectACL` on Gate middleware). Restricted JWTs get **403** on non-member `X-Project-ID`; role `admin` stays unrestricted. No second membership store — hub-minted claims only.
- Run lifecycle: `POST /api/perf/runs` writes `created` when undispatched and `failed` when dispatch errors (no more stuck `running`); `POST /api/perf/runs/{id}/cancel`.
- SLA gate JSON includes `pass` alongside `ok`/`status`.
- Docs: tenant headers required for `GET /api/perf/scenarios` and `GET /api/perf/runs` when auth is on; NAS curl examples in interop/perf-lab.
- Auth via Open-Auth-Go `Gate` (delete local `auth.go` / `auth_local.go` duplicates).
- Qualify Perf Lab tables with `CLICKHOUSE_DB` via `chTable()`; hub tenant tables use `hubTable()` (`opa`).
- Create `load_*` schema in the product database on startup.

- Product branding: Open Perf Lab (`opl-api` / `OPL-API`).
